# 12 公開リポジトリの入れ替え

## 背景
これまでのリポジトリは公開の設定で、main の履歴に予約番号・チェックインQR・塗りつぶす前のPDFが残っていた。このため、次のように分ける。
- 今のリポジトリは、名前を `Nara-Osaka-Trip_2026-dev` に変えて非公開にした（利用者が実施済み）。
- 同じ名前 `Nara-Osaka-Trip_2026` で新しい公開リポジトリを作った（中身は空。利用者が実施済み）。
- 公開用には、main の「中身だけ」を履歴なしで入れる。URL は今までと同じになる。

作業は、非公開になった作業用リポジトリ（このセッションのリポジトリ）で行う。

## 作業
A. 「トンネルの中のすれ違い」のトリビアから、出典で裏付けられない部分（大きな音と揺れになる、など）を削り、出典どおりの短い文にする。キャッシュ名と `?v=` を1つ上げる。お知らせは今回は足さなくてよい。
   - 作業ブランチ → main へマージコミットで取り込む（今までどおり）。
B. `_指示文/公開手順.md`（ブランチ `claude/web-design-production-gbwf3b` にある）を読み、その手順どおりに公開用リポジトリへ初めての公開をする。
   - 公開用の最初のコミットは1つだけ。作業用の履歴・ブランチは一切持ち込まない。
   - 公開用リポジトリに push できない場合は、そこで止めて、何が足りないか（GitHub のアプリの権限など）を報告する。
C. 公開用リポジトリの GitHub Pages の設定は利用者が行う。push が終わったら「Pages を設定してください」と伝える。設定後に URL が開けること、キャッシュ名が新しいこと、合言葉で開けること、オフラインで開けることを確かめる。
D. 作業用リポジトリの内容・履歴・ブランチは消さない。書き換えない。

## 報告
- A の新しい文
- 公開用リポジトリの中身の一覧（フォルダとファイル名だけ）と、点検の結果（種類だけ）
- 公開用リポジトリの履歴が1コミットだけであること
- 公開中の URL と、新しい版になったかどうか
- 利用者が行う残りの作業があれば、その手順
