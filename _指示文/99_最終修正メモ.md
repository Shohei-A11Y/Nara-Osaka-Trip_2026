# 最終修正メモ（ユーザー要望 ＋ 相談役の意見）

## ① 初回ガイド（コーチマーク）
- 要望：初めて開いたとき、「○○はここ（次へ／スキップ）」のような案内を出す。
- 意見：
  - 4〜5ステップまでにし、どの画面からでもスキップできるようにする。
  - 一度見たら表示しない。この記録は端末ごとの保存でよい。
  - メニューの「使い方」から、いつでも見直せるようにする。
  - 案内は②のナビゲーションの各ボタンを指す作りにし、②とセットで実装する。

## ② 迷わないナビゲーション
- 要望：同じ種類の機能は一か所にまとめる。スクロールしても常に表示される帯（ヘッダーかフッター）から、各ページへ行けるようにする。
- 意見：
  - **画面下に固定のタブバー**を置く。スマホで親指が届く位置になる。
    - 4〜5個まで。例：きょう／日程／のりもの／まっぷ／その他。
    - 「その他」を押すと、下から一覧が出てくる。持ち物や連絡先などの道具は種類ごとにまとめて並べる。
  - 三本線メニューは、中身が見えないので迷いやすい。補助として使う程度にする。
  - **「きょう」タブ**：日付と時刻から、今いちばん必要な情報（次の列車・次の予定）を自動で一番上に出す。旅行中は、アプリを開けばまずこれを見る、という使い方になる。
  - 新しい機能は、必ずこのタブのどれかに入れる。

## ③ トップのイラスト
- 要望：大阪のかわいいアイコンを鹿の近くに追加する。新幹線の簡単なイラストが、左右どちらかから画面に現れて横切り、反対側へ消えていく演出を付ける。
- 意見：
  - 大阪のモチーフは、**たこ焼き・大阪城・通天閣の影絵**など一般的なものにする。くいだおれ太郎やビリケンなどの実在キャラクターは避ける。
  - 新幹線はCSSのアニメーションで動かす。
    - 開いたときに1回だけ走らせる。タップするともう一度走る。
    - 鹿が少し跳ねて反応すると、なおかわいい。
    - 端末の「視差効果を減らす」設定がオンのときは止める。
    - 動いている間も、画面の他の部分はタップできるようにする。

## ⑦ ライブ地図の改善（ユーザーの見直し 2026-09-28）
- 前提：利用端末は Pixel 8 Pro×2（Chrome）、iPhone×2（Safari）。どちらでも動くこと。実機確認も両方で行う。
- 見どころのピン
  - 漢字1文字のアイコンをやめ、ピンを立てて横にスポット名だけを出す。地図を傾けてもピンと名前は画面に向かって立てる（地図に寝かせない）。
  - 距離で濃さを変える：遠いものは薄く小さく、近づくと濃く大きく、通り過ぎたら薄く。窓から見えるもの・いちばん近いものははっきり。薄い名前同士が重なるときは遠いほうの名前を隠す。
  - 種類ごとに色分け（4〜5色：城／寺社・史跡／自然／街・施設など）。朱・藍・深緑・からし色など落ち着いた色。色だけに頼らずピンの頭に小さな記号。隅に開閉できる凡例。窓から見えるものは白い縁取りなどで区別。
  - 名前をタップすると、詳細を下から出るカードで表示（地図の上の吹き出しにはしない）。
- 角度と向き
  - 2本指の上下で傾きを変えられるようにする。自動追尾で角度を戻さない。「立体／平面」ボタンの表示は今の角度に合わせて変わり、押すと55度／0度へなめらかに。角度は端末に保存。上限70度のまま。
  - 右上に方位磁針（赤い側が北）。押すと「北が上」⇔「進行方向が上」を切り替え（立体でも使える。傾きは保つ）。北が上の間は追尾しても回さない。2本指で回したらその向きで止め、方位磁針で戻す。選択は端末に保存。
  - 右上のボタン群（方位磁針・立体／平面・地図の種類・現在地へ戻る・全画面）は押しやすい大きさで縦にまとめる。
- 地図の種類の切り替え：地理院 標準／地理院 淡色／地理院 航空写真／OpenStreetMap（出典表記を付ける）。選択は端末に保存。
  - Yahoo地図・Googleマップは規約上組み込まない。代わりに「Googleマップで開く」ボタン（現在地・スポット）。
  - 航空写真は通信量が多い旨を一言。電波が弱いときは標準地図に戻す。
- 電池を抑える（表示はすぐ始まる形のまま）
  - 地図の描き直しは3〜5秒に1回。列車の印は合間になめらかに動かす。
  - 画面を離れた・アプリを閉じた・画面が消えた・地図が画面外にスクロールされたときは、地図の更新とGPSを止める。戻ったら即再開。
  - 本物のGPSはボタンを押したときだけ（今のまま）。取得は数秒おき。トンネルでは時刻表からの推定に任せる。
  - 高解像度の画面では少し粗めに描く。
  - 「省電力」スイッチ：更新10秒に1回・平面・淡色・航空写真なし・「画面を自動で消さない」をオフ。Pixel は電池残量が少ないとき自動で省電力に（Battery API）。iPhone は手動のみ。
- 向かいの列車の表示（鉄道Now風）は見送り。
  - 公式の走行位置データがなく、時刻表から推定するとデータ作りが重く、すれ違いとも一致しないため。
  - 代わりに「ほかの列車の走行位置を見る」外部リンク（JR西日本など公式。新幹線が対象か実装時に確認し、なければ付けない）と、すれ違いの豆知識を鉄道トリビアに。
- 画面の構成
  - 最初の1画面に、地図・次の停車駅と残り時間・速さ・窓側の見どころを収める（地図の高さは画面の高さから自動で決める）。駅の一覧・見どころ一覧は下へスクロールして見る。
  - 通常の画面では、1本指はページのスクロール、2本指で地図を操作（MapLibre の cooperativeGestures 相当）。1本指で触れたら「地図は2本指で動かせます」と一瞬出す。
  - 「全画面で見る」ボタンで地図だけの専用画面へ（直接開けるURLにする）。次の駅・到着時刻・お知らせは半透明の札で重ねる。専用画面では1本指で地図を動かせる。左上に「戻る」。きょうタブや列車カードからもリンク。
- 「画面をつけたままにする」→「画面を自動で消さない」のオン・オフスイッチに。説明：「スマホは、しばらく触らないと暗くなって消えます。オンにすると、このページを開いている間は消えなくなります。そのぶん電池を多く使います。」
- 降車のお知らせ
  - ボタン名は「アラーム／バイブをONにする」。初期は音なし（バイブ＋画面）。下に「音：なし／あり」。音ありは短い1音・控えめ。
  - 説明：「新大阪の5分前と1分前にお知らせします。初めは音を出さず、バイブと画面で知らせます（iPhoneは画面のみ）。」（到着駅は列車に合わせる）
  - バイブ（Pixel）：5分前は短く2回、1分前は長めに3回。
  - 画面のお知らせ：上半分に朱色の大きな札（例「まもなく新大阪　あと5分」）、縁がゆっくり数回光る。約15秒で画面の端の小さな印（例「新大阪 5分」）に縮み、残り時間を数え続ける。タップで詳細（到着時刻・降りる側のドア・乗り換え）。到着したら消える。
  - スマホの通知：Pixel はロック画面に通知し、1〜2分で自動で消す。1分前の通知は5分前の通知を置き換える（同じ tag）。タップでライブ画面を開く。iPhone はホーム画面に追加して開いている場合だけ試し、出せなければ画面のお知らせのみ。
- おためしモードの入口：今は目次の最下部とトップの最下部だけで見つけにくい。②のタブバーの「その他」から開けるようにし、①の初回ガイドでも一度案内する。

## ⑧ 相談役の提案（ユーザー了承済み。2本目の指示「全体のデザイン」で行う）
- 予約番号とQRに合言葉の鍵をかける（ユーザー決定。この方式に変更済み）
  - 対象は、ホテルの予約番号とチェックインQRの中身だけ。料金・電話・住所はそのまま。
  - 公開ファイルには暗号にした形だけを置き、暗号にしていない値は data.js から消す。
    - 暗号化はブラウザ標準の Web Crypto で行う（PBKDF2 で合言葉から鍵を作り、AES-GCM で暗号化）。新しいライブラリは入れない。
  - 初めて見るときは、合言葉を1回入れる。正しければ端末（localStorage）に覚えさせ、以後はこれまでどおり表示する。
    - 合言葉を入れる画面では「合言葉は家族のLINEで確認してください」と案内する。
    - 間違えたときは、落ち着いた文面で知らせる。
  - 「画像として保存」ボタンを付ける。予約番号とQRを1枚の画像（PNG）にして、スマホに保存できるようにする。控えとして使う。
  - その他に「この端末の合言葉を消す」を置く。
  - 合言葉は利用者が実装セッションに直接伝える。リポジトリ・コミット・報告には、合言葉も、暗号にしていない値も書かない。
  - 過去のコミットには、暗号にしていない値が残る。ユーザーは、履歴の書き換えはしないと決めた（(a)）。
- 文字の大きさの切り替え：「その他」に「文字を大きく」（標準／大）。端末に保存する。
- 電波がないときの確認：完成時に、機内モード相当（オフライン）で全画面が開けることを確かめる。

## ⑪ アプリのアイコンとホーム画面への追加（2本目で実施・ユーザー承認済み）
### アイコン

- 差し替えるファイル：`assets/icon.svg`（ブラウザのタブ用）、`assets/icon-192.png`、`assets/icon-512.png`（Playwright で SVG から書き出す）。

  - 鹿の絵は、Android で丸く切り抜かれても欠けない位置に収めてある。
### 「ホーム画面に追加しますか？」の案内
- **いつ出すか**
  - しおりを初めて開いたとき。
  - 「あとで」を選んだ場合は、次に開いたときにもう一度出す。
  - 「今後は表示しない」と、すでにホーム画面から開いている場合は出さない。
  - ホーム画面から開いているかの判定は `display-mode: standalone` と `navigator.standalone` で行う。
- **Android（Chrome）**
  - `beforeinstallprompt` を取っておき、「はい」を押したら `prompt()` を呼ぶ。
  - 端末の確認画面で「追加」を押すだけで登録が終わる（ブラウザの仕様で、確認画面は省略できない）。
- **iPhone（Safari）**
  - ホーム画面へ自動で追加する方法はない。
  - 「はい」を押したら、手順を図で示すシートを出す。
    1. 画面下の共有ボタン（□に↑）を押す。
    2. 「ホーム画面に追加」を押す。
    3. 右上の「追加」を押す。
  - 共有ボタンのある下の方向を、矢印で指し示す。
- **LINE などのアプリの中で開いている場合**
  - アプリの中のブラウザではホーム画面に追加できない。
  - 「Safari（Android は Chrome）で開き直してください」と案内し、URL のコピーボタンを付ける。
- **いつでも追加できるようにする**：その他タブに「ホーム画面に追加」を置く。
- **見た目**：ことりっぷ調の落ち着いた下からのシートにする。新しいアイコンを添えてよい。うるさくしない方針（⑩）を守る。
- **初回ガイドとの順番**：ホーム画面の案内を先に出し、ライブ地図のガイドとは重ならないようにする。

## ⑬ 使い方ページ（3本目で実施。2本目が終わって画面が固まってから）
- **置き場所**：その他タブに「使い方」を置く。開くと、機能ごとのタイルが並んだ目次になる。
- **1つの機能＝1枚**：各項目は「実際の画面の写真＋番号の吹き出し＋1〜2行の説明」だけにする。長い文章は書かない。
