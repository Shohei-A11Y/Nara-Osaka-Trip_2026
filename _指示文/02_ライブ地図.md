# ライブ地図（のぞみ車内用）実装指示

リポジトリ：Shohei-A11Y/Nara-Osaka-Trip_2026（GitHub Pagesで公開中の家族旅行しおり。素のHTML/CSS/JS）
作業ブランチ：`claude/live-map` を main から作成して作業する。

## 目的
新幹線のぞみの車内で開くと、地図の上で「いまどこを走っているか」が分かるページにする。
**既存の「のぞみ いまどのへん？」（`#/ride/live/nozomi28`・`#/ride/live/nozomi17`）を拡張する。** 新しいページは作らない。
使うのは家族（スマホ、主にiPhoneのSafari）。見やすく、迷わず、電池を食いすぎないことを優先する。

## 最初に読むもの（読むのはここだけで足りるはず）
- `assets/app.js`：`viewLive()`・`updateLive()`・`liveState()`（600行目付近）。おためしモードのシナリオ一覧（188行目付近）も読む。
- `assets/sim.js`：`Clock`（仮想時計）と `Geo`（本物のGPSと作り物の位置の切り替え）。ライブ地図で使う前提で作ってある。
- `assets/data.js`：`trains`・`nozomiLine`（19駅と時刻）・`nozomiTips`・`castles`・`seats`。
  - このファイルには予約番号などの個人情報が入っている。**中身をログや報告に書き写さない。**
- `sw.js`：オフライン用のキャッシュ。

## 画面の構成（上から順に）
1. **地図**（画面の高さの半分くらい）
   - 斜めから見下ろす3D風の表示にする（pitch 45〜60°）。
   - 線路の線、駅の点と名前、見どころのアイコン、自分の列車のマーカーを出す。
   - マーカーは進行方向を向ける。地図は列車を追いかけて動く。
   - 指で動かしたら追従を止め、「現在地に戻る」ボタンを出す。
   - 右上に切り替えボタンを置き、真上から見る平面表示にもできるようにする。
2. **情報パネル**（大きな文字）
   - 「現在地：○○県○○市付近を走行中」
   - 速度：「時速 ○○○km」
   - 次の停車駅：「つぎは 岡山　あと ○○km・約○分（13:57着）」
   - 情報の出どころを小さなバッジで示す：「GPS」または「時刻表から推定」。
3. **お知らせ**（必要なときだけ出す）：見どころの接近、トンネル、降車アラーム、乗り換え。詳しくは下の「おまけ機能」。
4. **既存の路線図**（縦の19駅リストと豆知識）
   - 今の見た目のまま、地図の下に残す。
   - 地図が読み込めないときは、この部分だけで今までどおり使えるようにする。

## 地図の作り方
- **ライブラリ：MapLibre GL JS**
  - npm から取得し、`assets/vendor/maplibre-gl/` に置いて自前で配信する。オフラインでも動かすため。
  - 作業用コンテナでは jsdelivr が遮断されていることがあるので、CDNに頼らない。
  - バージョンは固定する。
- **背景地図：国土地理院の地図タイル**
  - 淡色地図、または標準地図のラスタータイル。APIキーは不要。
  - 出典表示「地理院タイル」を必ず入れる。
  - 陰影起伏図を薄く重ねると立体感が出る。重くなるなら省略してよい。
  - 地形の3D表示（terrain）は、手間と重さに見合わなければ入れなくてよい。
- **線路の形**
  - 国土数値情報「鉄道データ（N02）」から、山陽新幹線の 新大阪〜博多 だけを抜き出す。
  - 間引いて軽くした GeoJSON（目安100KB以下）を `assets/line-sanyo.json` として同梱する。
  - 出典表記を入れる。
  - ダウンロードが遮断されて取得できない場合の代わりの手順：
    - 駅の座標と、既知の経由地点をつないだ粗い線で代用する。
    - 報告に「線路の形は仮」と明記する。
- **駅データ**
  - 19駅それぞれに、緯度経度と新大阪からの距離（キロ程）を持たせる。
  - 置き場所は `data.js` とは別のファイル（例：`assets/line-data.js`）にする。

## 位置の決め方（いちばん大事）
次の2つを組み合わせ、線路上の「新大阪から何km地点か」という1つの数値で管理する。

- **A. 時刻表からの推定**
  - 既存の `liveState()` の考え方を使う。
  - 駅と駅の間は、距離に比例して進むとみなす。
- **B. GPS**
  - `Geo.watch()` で位置を受け取る。
  - 線路に吸着させて、キロ程に変換する。
  - 次の条件のときは信用しない：
    - 線路から500m以上離れている
    - 精度が1kmより悪い
    - 30秒より古い

組み合わせ方：
- GPSが使えるときはGPSを採用する。
- そのときに「時刻表とのずれ（遅れ○分）」を記録しておく。
- GPSが途切れたとき（トンネルや圏外）は、時刻表の推定に記録済みのずれを足して進める。
- 停車駅で止まっているときは、その駅に固定する。
- マーカーは一瞬で飛ばさず、滑らかに動かす。
- 遅れが2分以上なら、情報パネルに「約○分遅れ」と出す。これはGPSで判断できるときだけ。

**速度**
- GPSの速度値があれば使う。
- 無ければ、直近の2〜3点から計算する。
- どちらも無ければ、時刻表の区間平均を「約○○km」と出す。
- 停車中は0にする。
- 数値が跳ねないように、なめらかにする。
- 列車の速度は最高でも300km/hなので、330km/hを超える値は捨てる。
- **`sim.js` の Geo は今は speed・heading を渡していないので、追加する。**

**市町村名**
- 走行中にネットで問い合わせるのではなく、事前に計算して同梱する。
  - 線路に沿って「○km〜○kmは○○県○○市」という区間の表にする。
- 作り方：線路上を約1km間隔でたどり、国土地理院の逆ジオコーダ（LonLatToAddress）で市区町村コードを調べる。コード表は地理院の muni.js を使う。
- 区間が変わる境目だけを残して、`assets/line-data.js` に入れる。
- 逆ジオコーダに作業環境から届かない場合の代わりの手順：
  - 実装は済ませる。
  - 表は駅の所在市町村と、駅間の中点での切り替えで仮に作る。
  - 報告に「市町村は仮」と明記する。

## 見どころ
しおりに載っているスポットだけでなく、**沿線の見どころ**を広く集め、近づいたら紹介する。2種類に分けて扱う。

- **窓から見えるもの**
  - 既存の `castles`（三原城跡・福山城・姫路城）に加え、車窓から実際に見えるものだけを入れる。
    - 例：瀬戸内海が見える区間、大きな川や橋、目立つ山など。
  - 見える側（北・南）を持たせる。
  - 確かでないものは入れない。
- **この近くにあるもの**（窓から見えなくてよい）
  - 線路からおおむね15km以内の名所・名物・ゆかりの地を、区間ごとにまんべんなく拾う。目安は全体で40〜60件。
    - 例：関門海峡、錦帯橋、宮島、尾道の町並み、倉敷美観地区、岡山後楽園、明石海峡大橋、有馬温泉など。
  - 1件につき持たせるもの：
    - 名前
    - 緯度経度
    - ジャンル（城・自然・町並み・食・温泉など）
    - 2〜3行の紹介文。子どもにも分かる言葉で書く。
    - 公式サイトなどのリンク（任意）
  - 紹介文は、確かな事実だけで書く。自信のない数字や由来は書かない。

**表示のしかた**
- 地図上：
  - 小さなアイコンで出し、タップすると紹介カードが開く。
  - ジャンルで色分けする。
- お知らせ：
  - 「窓から見えるもの」は、近づいたら（到達の約5分前）目立つ形で出す。
  - 「この近くにあるもの」は、最寄りの地点を通るころ、控えめなカードで1件ずつ出す。「いま近くには…」のような形にする。
  - 同時にたくさん出さない。
- データは `assets/line-data.js` などにまとめて同梱する。走行中にネットで検索はしない。
- 座標や紹介文を作業環境で確かめられなかったものは、報告の「仮」の欄に件数を書く。

**「窓から見えるもの」のお知らせの例**（到達の約5分前）：
  - 「まもなく姫路城　右の窓（北側）＝ D・E席側」
- **見える側の考え方**
  - E席の窓は常に北側（山側）。
  - この一家は往路・復路ともD・E席なので、北側の見どころは自分の窓から見える。
  - 南側（海側）の見どころは「通路の反対側の窓」と案内する。
  - 左右は進行方向で決まる：往路（東行き）は北＝左、復路（西行き）は北＝右。
  - 既存の `updateLive()` の左右の表記とそろえる。

## おまけ機能
- **トンネル**
  - 長いトンネル（2km以上）の区間をキロ程で持つ。
  - トンネル内はこう表示する：「トンネル内（出口まで約○分）・GPSは一時的に届きません」
  - 数は主要なもので構わない。
- **降車アラーム**
  - 往路は新大阪、復路は博多で降りる。のぞみ28号は新大阪が終点ではないので、特に大事。
  - 5分前：画面上部に目立つ帯を出す。「まもなく新大阪。降りる準備を（荷物・上着・切符）」
  - 振動も出す（`navigator.vibrate` が使える端末のみ）。
  - 1分前：もう一度知らせる。
  - 音は、ページ上の「アラームをONにする」をタップしたあとだけ鳴らす。iPhoneの制約のため。
- **乗り換えカウントダウン**
  - 復路の博多到着が近づいたら、こう出す：「リレーかもめ33号 13:54発まで あと○分（乗り換え24分）」
  - 往路の新大阪到着前は「ホテルのチェックインは15:00から」を出す程度でよい。
- **画面を消さない**
  - Screen Wake Lock API が使えるなら、トグル「画面をつけたままにする」を置く。初期値はOFF。

## おためしモード（シミュレーション）
- 既存のおためしモードに、ライブ地図用の再生を追加する。
- 「のぞみ28号・福山の手前」などのシナリオを選ぶと、次のように動くようにする：
  - 仮想時計（×1／×10／×60）に合わせて、作り物のGPSが線路上を進む。
  - 位置には数十mの揺れを混ぜる。
  - トンネル区間ではGPSを止め、推定に切り替わる様子が見える。
  - 「5分遅れ」のシナリオも1つ用意し、遅れ表示とアラームのずれを確かめられるようにする。
- おためし中は本物のGPSを要求しない。
- 本物の位置もどこにも送らない（地図タイルの取得を除き、外部通信なし）。

## 守ること
- 既存の機能・見た目・URLを壊さない。
- 路線図・豆知識・城のお知らせは、地図の下で今までどおり動くこと。
- 位置情報の許可は、ページ上のボタン「現在地を使う」を押したときに初めて求める。
  - 拒否されたら、時刻表の推定だけで動く。
- GPSは、このページを開いている間だけ使う。
  - ページを離れたとき、またはタブが非表示になったときは止める。
- `sw.js` の更新：
  - MapLibre 本体・`line-sanyo.json`・`line-data.js` を事前保存に入れる。
  - 地図タイルは、見た分だけを保存する。保存の上限はおよそ300枚にし、古いものから消す。
  - キャッシュ名と `?v=` を上げる。
- デザインは今のことりっぷ調（和紙色・明朝・朱）に合わせる。
  - 地図の枠・パネル・ボタンは既存のCSSの変数とクラスを使う。
- 将来、画面下のタブバー（きょう／日程／のりもの／まっぷ／その他）を入れる予定がある。
  - このページは「のりもの」の中に入る前提で、単独でもメニューから行ける今の導線は維持する。
- data.js の個人情報を、新しいファイルや報告に写さない。

## 確認
- 同梱の Chromium と Playwright で、スマホ幅（390×844）の画面を確認する。
  - 往路・復路の両方を、おためしで ×60 で最後まで流す。
  - 次の点を確かめる：
    - 地図が表示される
    - マーカーが線路上を進む
    - 市町村名・速度・次の駅の表示が変わる
    - トンネルで推定に切り替わる
    - 降車アラームが出る
    - 遅れシナリオで遅れが表示される
  - スクリーンショットを数枚残す。
  - 作業環境から地理院タイルに届かない場合は、背景なしで確かめ、その旨を報告に書く。
- 地図が読み込めない状態にしたとき、既存の路線図だけで動くことも確かめる。
- コンソールにエラーが出ないこと。

## 完了したら
- `claude/live-map` に commit・push する。
- 確認がすべて通ったら、main にマージして公開してよい（ユーザー了承済み）。
  - マージは、問題があれば元に戻しやすい形で行う。
  - 確認が通らない場合は、マージせずに報告する。
- 報告は短く、次の形でまとめる：
  1. できたこと（箇条書き）
  2. 「仮」のもの（線路の形・市町村・見どころの位置など、推定や代わりの手順で作ったもの）
  3. ユーザーが実機で確かめる手順（3〜5行。おためしで見る方法を含む）
  4. 気になった点
- 途中で質問は極力せず、上の方針で判断して進める。
